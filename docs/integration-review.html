Querent v2: integration review

Where an external system can connect, what could break, and what to test. Evidence from the code at commit 5a60741 (main).

Overview

Querent is one Next.js process with one SQLite file. External systems can reach it today only through its HTTP API (cookie session), by writing the SQLite file directly, or by running code inside the same process. It calls exactly one external service at runtime: the Anthropic API. It has no webhooks, message queues, file imports, outbound events, or order write-back.

Bottom line for an integration

No ready-made inbound data path exists. The ERP-sourced tables carry source, external_id and synced_at with a unique index, but no code reads or writes rows by (source, external_id). Every row today has source='seed'. A sync must be written from scratch.

Absent integration mechanisms

There is no webhook sender or receiver, no message queue, no outbox, no file upload or import endpoint, no Next.js middleware, and no outbound HTTP call from server code except through the Anthropic SDK. A search for webhook, queue and fetch( in src/server finds none; the only API route files are the 36 listed above; no middleware.ts or proxy.ts exists.

Open questions

Could not verify from the code

Whether claude-sonnet-5 (the default model ID) is accepted by the Anthropic API, and whether the SDK retries on the errors you expect. src/server/chat/mode.ts:8, src/server/chat/live.ts:46

How SQLite behaves under concurrent writers from more than one process. No busy_timeout is set in db(); the library default applies. src/server/db/index.ts:11-23

Request body size limits and timeouts for route handlers. They are framework defaults; no code sets them.

Whether next build needs network access for next/font/google in your build environment. src/app/rep/layout.tsx:5, 15-17

The ERP's ID formats, currencies, tax rules, units of measure, number of ship-tos, and time zone. The code fixes all of these; whether they match is outside the code.

Questions for you

  1. Which external system, and which direction: an ERP pushing master data in, Querent pushing accepted quotes out, or both?
  2. Will the integration run in the Next.js process, as a separate worker sharing the SQLite file, or only over HTTP?
  3. Do ERP item ids equal SKUs? Querent looks items up by "id or SKU", and the seed sets them equal.
  4. Does the ERP use one currency (USD), quote totals before tax, and integer pack quantities?
  5. Which time zone defines "valid until"? Today expiry uses UTC days but pickup slots use Mountain time.
  6. What replaces the persona cookie, and how do your users map to customer_id, contact_id and rep_id?
  7. Should settings changes (customer access, rep assignment, delivery rates) be restricted per rep and audited?
  8. Will more than one instance of the app run? If yes, idempotency and caches must move out of process memory.
  9. Must accepted quotes become ERP orders, and should quotes store the ERP order or quote number?
